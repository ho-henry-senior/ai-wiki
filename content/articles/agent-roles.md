# Agent roles

An **agent role** describes what an agent is responsible for, the boundaries on its work, and what it hands back to another agent or a person. Roles can help when a task genuinely needs distinct responsibilities or independent review, but more roles also mean more coordination.

This guide follows three connected questions: how to define a role, how roles can work together, and what role instructions look like in a concrete example. Each page can also be read on its own.

## Read the guide

1. [Agent roles, skills and tools](../concepts/skills-profiles-and-tools.md) — distinguish responsibilities from reusable procedures and executable capabilities, then define a role contract.
2. [Agile roles in agentic development](agent-role-boundaries.md) — explore a small illustrative workflow, explicit handoffs, and human approval boundaries.
3. [How agent roles use skills](../reference/agent-roles-directory.md) — inspect source-linked role files from a case study, including their use of skills.

## When to use roles

Start with one agent and a human reviewer. Introduce specialist roles only when clear responsibilities and handoffs improve a recurring workflow. Keep human approval explicit where scope, access, or release decisions matter.

For reusable task procedures rather than responsibilities, follow the [Skills guide](../goals/economy/useful-skills.md). The comparison in [Skills and agent roles](skills-and-agent-roles.md) can help you choose between them.
