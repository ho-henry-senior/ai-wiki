# Skills as a changing capability layer

Skills are one way to give an agent reusable, task-specific knowledge or procedures. They can help when an agent repeatedly needs guidance, examples, or a workflow that the harness does not provide well by itself.

The boundary between a skill and a harness capability is not fixed. A skill may provide value now, then become less necessary when a harness incorporates equivalent support. Treat skills as a changing layer in the agent ecosystem, not a timeless set of add-ons.

## What makes a skill worth considering?

For this collection, a skill is a candidate for recommendation when it:

- addresses a real, recurring task or pain point;
- adds value beyond the harness's current built-in capabilities; and
- has practical evidence or experience behind it.

These are curation criteria, not a universal definition of skill quality. A skill's usefulness can also depend on its scope, maintenance, compatibility, and the task at hand.

## Keep recommendations current

A useful list should be organized around the problem or capability a skill addresses, with harness-specific support noted for each entry. Record when an entry was last reviewed and whether an equivalent capability is now built into a harness.

If a harness absorbs a capability, retain that information with a clear status rather than silently treating an external skill as still necessary. This preserves the useful pattern and makes the changing boundary visible.

See the [current useful-skills list](useful-skills.md), the [skills/profile guide](skills-and-agent-profiles.md), and the [skills, profiles, and tools distinction](../concepts/skills-profiles-and-tools.md).

## Keep concepts portable

Describe the need a skill addresses separately from how a particular harness installs or invokes it. Use Copilot as a concrete example where useful and label product-specific details. Keep other products' setup guidance outside this wiki's scope.

For an illustrative repository layout that separates skills from agent-oriented reference documentation, see [A structure for agent-facing repositories](agent-facing-repository-structure.md).
